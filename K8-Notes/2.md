## Module 1: Course Overview

**Core Concepts**  
- Kubernetes (K8s) is an open-source **container orchestration platform**.  
- It automates deployment, scaling, and management of containerized applications.  
- Solves real-world problems that exist when using Docker alone on servers.

**Problems Kubernetes Solves**  
- Manual server management  
- Scaling failures  
- Downtime during application updates  
- Inconsistent environments (dev/test/prod) — “it works on my machine”

**Key Orchestration Features**  
- Auto-scaling  
- Self-healing  
- Load balancing  
- Rolling updates  
- Secret management  
- Multi-environment consistency

**Notes**  
- Kubernetes is **declarative**: you describe the *desired state*, Kubernetes makes it happen.  
- Perfect for learning on a laptop with Minikube.

## Module 2: What is Kubernetes?

**Core Concepts**  
- Kubernetes is a **container orchestrator**.  
- It manages hundreds or thousands of containers across a cluster of machines.  
- Abstracts away infrastructure so developers focus only on their applications.

**Basic Points**  
- Pre-K8s: bare metal or VMs → “works on my machine” issues.  
- Containers + orchestration = portable, scalable, resilient apps.  
- Works on any cloud, on-prem, or hybrid.

**Notes**  
- Kubernetes ≠ Docker. Docker is just one possible container runtime.  
- Core concepts remain the same even as versions evolve.

## Module 3: Main Kubernetes Components

**Core Concepts**  
- **Node**: Physical or virtual machine.  
- **Pod**: Smallest unit in K8s — usually 1 container (can be 2-3 tightly coupled). Pods are ephemeral.  
- **Service**: Stable IP/DNS name + load balancer for Pods.  
- **Ingress**: Exposes HTTP/HTTPS routes from outside the cluster.  
- **ConfigMap**: Non-sensitive configuration data.  
- **Secret**: Sensitive data (passwords, keys).  
- **Volumes**: Persistent storage (survives pod restarts).  
- **Deployment**: Manages stateless apps (replicas, rolling updates).  
- **StatefulSet**: Manages stateful apps (databases) with stable identity.

**Basic Points**  
- Most apps use Deployment + Service.  
- ConfigMap/Secret are injected into Pods as env vars or files.  
- Everything in Kubernetes is a **resource**.

**Notes**  
- Use `kubectl` to interact with all resources.

## Module 4: Kubernetes Architecture

**Core Concepts**  
**Control Plane (Master)**  
- **API Server**: Central brain — all requests go through it.  
- **Scheduler**: Decides which Node a new Pod runs on.  
- **Controller Manager**: Runs controllers (Deployment, ReplicaSet, etc.).  
- **etcd**: Highly available key-value database — single source of truth for all cluster state.

**Worker Nodes**  
- **Kubelet**: Agent that runs on every node.  
- **Container Runtime** (Docker/containerd).  
- **Kube-proxy**: Handles networking and load balancing.

**Basic Points**  
- In production: multiple master nodes for high availability.  
- etcd must be backed up — if it fails, the cluster fails.

**Notes**  
- In Minikube (local learning): Control Plane + Worker run on **one machine**.  
- You rarely manage the control plane directly as a beginner.

## Module 5: Minikube & kubectl - Local Setup

**Core Concepts**  
- **Minikube**: Creates a single-node Kubernetes cluster on your laptop.  
- **kubectl**: Official command-line tool to talk to any Kubernetes cluster.

**Basic Commands**  
- `minikube start`  
- `kubectl version`  
- `minikube dashboard` (opens web UI)  
- `minikube status`

**Notes**  
- Zero cloud cost — ideal for learning.  
- All `kubectl` commands work exactly the same on cloud clusters.

## Module 6: Main kubectl Commands

**Core Concepts**  
- **Imperative** commands (quick, for learning) vs **Declarative** (YAML files — production standard).  
- `kubectl get <resource>` → quick overview  
- `kubectl create deployment ...` → imperative  
- `kubectl describe <resource>` → detailed info  
- `kubectl logs <pod>`  
- `kubectl exec -it <pod> -- /bin/sh`  
- `kubectl delete <resource>`  
- `kubectl scale deployment <name> --replicas=5`

**Basic Points**  
- `kubectl get all` is your daily best friend.  
- Use `-o wide` or `-o yaml` for more details.  
- Add `-n <namespace>` or `--all-namespaces` when needed.

**Notes**  
- Always move to YAML files as soon as possible.

## Module 7: Kubernetes YAML Configuration Files

**Core Concepts**  
Every Kubernetes resource is defined in a YAML file and applied with:  
`kubectl apply -f file.yaml`

**Structure of Every YAML File**  
1. **Metadata** — name, labels, namespace  
2. **Spec** — desired state (what you define)  
3. **Status** — current state (managed by Kubernetes, never edit)

**Key Fields**  
- `apiVersion` (e.g., `v1`, `apps/v1`)  
- `kind` (Pod, Deployment, Service, etc.)  
- `metadata.labels`  
- `spec.template` (pod blueprint inside Deployment)  
- `spec.selector` (used by Services to match Pods)

**Labels + Selectors**  
Labels identify Pods (e.g., app: nginx).  
Selectors match labels so Services can find and route to the correct Pods.

Notes 
- YAML is indentation-sensitive (use 2 spaces).  
- Version-control all YAML files in Git.  
- kubectl get <resource> -o yaml shows the full live definition.  
- Declarative approach is the recommended way in real projects.

**Minimal Pod YAML Example**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
  - name: nginx
    image: nginx
    ports:
    - containerPort: 80
